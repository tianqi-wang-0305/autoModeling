# 输入收集与映射

## 1. 多文件夹收集

- 给定根目录列表；用 `find <root> -name "*.slx"` 收集模型，需求文档按 `*.docx / *.md / *spec*.json` 收集；
- 同名模型出现在不同路径时提示用户确认；记录每个文件的相对路径与来源根目录。

## 2. 模型盘点

- 每个模型（只读）：`model_overview(detail='interfaces')` → `model_read`（逐子系统）→ `model_query_params`（端口类型/阈值）→ `model_resolve_params`（标定值）；
- 归纳：组件清单、输入输出、主要逻辑、状态机；
- 若模型无法打开/编译，记录为“不可用”并继续其余模型。

## 3. 需求 → 组件 → 模型映射

- 按功能名 / 信号名 / 标定名自动匹配需求与模型组件；
- 无法自动匹配时按语义判断，并在报告中标注“推断”；
- 输出追溯矩阵；未覆盖项（无模型的需求、无需求的模型）显式列出。

## 4. 一致性自检

- 接口：模型端口 vs 需求接口表；
- 覆盖度：每个需求至少映射一个组件/模型；每个模型至少对应一个需求（否则标记多余功能）；
- 文档内部：追溯矩阵、接口表、功能规格相互引用一致。
