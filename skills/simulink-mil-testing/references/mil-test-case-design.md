# MIL 测试用例设计

## 1. 需求驱动（用户提供了需求文件）

解析：
- docx → 文本（python-docx / pandoc / MATLAB 读 word XML）；
- md → 直接读章节；spec JSON → 直接读 `inputs / outputs / calibrations / subsystems / assumptions`。

提取内容并建映射：
- 正常功能行为 → 正常场景；
- 边界/范围（Min/Max、阈值、枚举编码、单位）→ 边界值场景（阈值±1、min/max、越界）；
- 异常/故障处理（质量标志、故障计数、降级）→ 故障注入场景；
- 时序/防抖/超时（周期计数阈值）→ 持续多周期的时序场景；
- 状态机转移（状态进入条件、优先级、退出条件）→ 转移覆盖表。

每条需求至少映射一个场景，每个场景至少一条用例。用例字段：

| 用例ID | 需求ID | 目的 | 前置条件 | 输入时序 | 期望输出/判定 | 覆盖意图 |
|--------|--------|------|----------|----------|----------------|----------|
| TC-001 | REQ-1  | ...  | 上电复位  | t0~tN 波形 | 阈值/范围断言 | decision/MCDC |

## 2. 模型驱动（无需求文件）

用 `model_read` / `model_overview` / `model_query_params` 读模型并推导：

- 输入/输出：名称、类型、枚举编码、Min/Max → 等价类 + 边界值；
- 标定量（`cal_*`）：默认值与范围 → 边界与阈值；
- 子系统与 Stateflow：状态集合、转移条件、优先级 → 转移覆盖表（每个转移至少一次，每个状态进入/驻留至少一次）；
- 比较器/阈值/防抖/超时计数 → 恰好低于 / 等于 / 高于阈值的周期序列；
- 布尔逻辑组合（AND/OR/NOT）→ 真值表（见第 3 节 MCDC）。

生成原则：每个等价类 ≥1 例；每个边界（min/max/阈值±1）≥1 例；非法/异常值 ≥1 例；状态机/时序场景单独设计。

## 3. 覆盖矩阵（decision / condition / MCDC）

- **decision**：每个判定（relop、逻辑输出、if/switch 对应的布尔结果）的真/假分支各 ≥1 次；
- **condition**：每个布尔条件的 true 与 false 各 ≥1 次（允许与其他条件任意组合）；
- **MCDC**：对每个条件 C，存在两组输入：C 翻转、其余条件固定不变，且判定结果随之翻转。

MCDC 真值表法（示例：`out = A && (B || C)`）：

| A | B | C | out | 覆盖说明 |
|---|---|---|-----|----------|
| F | F | F | F   | A-F, B-F, C-F |
| T | F | F | F   | A-T（A 独立: 行2 vs 行1）|
| T | T | F | T   | B-T（B 独立: 行3 vs 行2）|
| T | F | T | T   | C-T（C 独立: 行4 vs 行2）|

每行标注覆盖了哪些条件的 MCDC/decision/condition 项，缺哪项就补哪行。

## 4. MIL 输入与判定要点

- 离散模型按采样周期给 timeseries（如 10ms 周期 → 每 0.01s 一个采样点）；
- 状态机/计数逻辑：防抖或超时阈值 N 周期 → 至少持续 N+1 周期才能观测到状态切换；
- 期望输出优先用 Simulink Test 的 Baseline（golden 输出）或关系判定（范围/阈值），手工写期望时考虑状态延迟与初始化周期；
- 异常输入区分“立即触发”和“计数/防抖后触发”两类场景。
- **每个用例同时输出 `.mat` 与 Excel（.xlsx）输入**：Excel 列为“时间 + 各输入信号（同名同类型）”，供用户手动变更优化；修改后重跑并重录 baseline。
- **覆盖门槛**：decision=100%、condition=100%、MCDC≥80%（目标100%）；用例设计阶段即按此规划覆盖矩阵，MCDC 不足时用真值表补组合。
